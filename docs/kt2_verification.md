# Проверка реализации КТ2

Первичная проверка выполнена 28.10.2026; повторная проверка после доработки
валидации — 02.11.2026. Среда: Windows, Python 3.13.9.
Использовались разовые проверки функций и запуск `python main.py` с вводом
в консоль на временных копиях `src/`. Отдельный тестовый фреймворк не добавлен.
Поставляемый `warehouse.json` сохранил исходные демонстрационные данные.

прототипа к запуску в рамках КТ2; полноценный этап тестирования КТ4 не выполнен.

## Что проверено в моделях и коде

- BPMN прошёл валидацию по официальным XSD BPMN 2.0 OMG.
- XML импортирован в bpmn-js 18.8.0, используемый для моделей bpmn.io:
  0 предупреждений, 198 элементов в реестре диаграммы, включая подписи и связи.
- Есть два пула, три дорожки, одно Start Event, одно End Event,
  шесть исключающих развилок, пять шлюзов слияния и шесть Message Flow.
- Все пять автоматизируемых serviceTask находятся в дорожке информационной
  системы; остальные действия распределены по сотруднику приёмки и кладовщику.
- Sequence Flow не пересекают границу пулов; развилки подписаны «Да»/«Нет».
- Есть десять объектов данных D1–D10 и направленные ассоциации чтения/записи.
- ER содержит восемь сущностей и семь непосредственных нормализованных
  связей с PK/FK и crow's foot. Product → Batch выводится через DeliveryItem
  по уточнению пользователя. M:N разрешена; SQL и типы хранения отсутствуют.
- Draw.io XML декодированы штатным mxCodec. PNG получены через штатный
  Graph.getSvg и Chromium с подключённой библиотекой маркеров ER.
  Визуально проверены атрибуты, crow's foot, тексты, парные границы циклов,
  подписи выходов и отсутствие обрезанных блоков.
- В алгоритме сопоставления AST содержит четыре цикла for и пять if;
  на схеме — C1–C4 и пять решений. Обе пары вложенных поисков сохранены.
- В алгоритме подбора — один for, семь if; на схеме — C5 и семь решений.
  Сортировки и накопления кандидатов нет. Время O(k), память O(1).
- Время сопоставления O(n·m+n+m), при непустых списках O(n·m).
- В Python нет собственных классов, dataclass, NamedTuple, Enum,
  изменяемых глобальных переменных и внешних зависимостей.
- Обязательные поля JSON совпадают с ER; проверяются PK/FK, уникальность
  позиции, фактические количества, суммы принятых партий и размещений,
  вместимость, режим и зона.

Исходные пять документов и файлы КТ1 не редактировались. Существующие
каталоги `docs/`, `python/`, `java/`, `database/` сохранены. В корневой README
добавлена ссылка на КТ2, в `.gitignore` — исключения Python-кэша.

## Границы проверки и Git

Все четыре PNG экспортированы; файлов, которые необходимо дорисовать или
экспортировать вручную, нет. Из-за ошибки графического процесса нативный CLI
draw.io не использован для конечного экспорта; использован его штатный
движок XML/SVG в Chromium. Интерфейс сайта demo.bpmn.io отдельно вручную не
проверялся: выполнены импорт тем же движком bpmn-js и XSD-валидация.

Java, ООП, диаграмма классов, физическая модель, СУБД, SQL, GUI,
организационная часть и рынок труда не реализованы. Текст КТ1 сохранён.
Отчёт оформляется отдельным файлом на рабочем столе; в итоговом архиве
он должен называться `report.docx`. Перед сдачей требуется актуальная
выгрузка реальной истории Git.

Ветка проекта: `kt2-analytical-stage`. В истории уже есть коммиты КТ2
`47698d1` от 31.10.2026 и `abbde02` от 01.11.2026. Доработки проверки JSON
и документации подготовлены для следующего содержательного коммита.

Адрес репозитория сохранён в `vcs/repo_url.txt`. После реального третьего
коммита обновите журнал для итогового архива из корня проекта:

```powershell
git log --all --date=iso --pretty=format:"%h %ad %an %s" |
    Out-File -LiteralPath vcs/git_log.txt -Encoding utf8
```

`git_log.txt` формируется Git и не редактируется вручную. Это генерируемый
файл комплекта сдачи; он исключён из отслеживания, чтобы выгрузка содержала
последний коммит и не требовала отдельного коммита самой выгрузки.

## Дополнительная проверка целостности JSON 02.11.2026

Отклонены 13 некорректных вариантов: неизвестные статусы поставки и ячейки;
статус размещения без поступления; принятие без партий; несоответствие
статуса полноте размещения; размещение раньше поступления; неизвестный тип
расхождения; неверные знак и величина недостачи; подмена недостачи излишком
или незаявленным товаром; пустое описание и ненулевая разность качества.
Каждый вариант проверен через `validate_data()`, `load_data()` и `save_data()`.
Неудачная запись оставляет прежние байты рабочего JSON без изменений.

Отдельный запуск с некорректным состоянием JSON завершился с кодом 1 и
понятным сообщением без traceback; исходный файл не изменился. Повторно
прошли исходные 14 групп, включая полный консольный маршрут и запись JSON.
Проверочные сценарии выполнялись вне репозитория, на временных копиях.
Отдельная инфраструктура тестирования в проект не добавлялась.
